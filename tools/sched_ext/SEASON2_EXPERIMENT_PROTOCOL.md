# Season 2 policy experiments

Lightweight Base and its technical/release tags are immutable. Start each `season2/<hypothesis>` branch from the reviewed portable Base commit. State one policy hypothesis, the exact Base commit, candidate commit and expected effect before measurements. Change scheduler policy as narrowly as possible; retain the existing llama runtime, phase transport and compact control state. No heavy permanent instrumentation, worker accounting, histories or continuous observers.

Use the same machine and generated host profile for neutral Base and candidate. Keep the exact model, frozen workload, affinity, compute/batch/HTTP threads and machine power configuration. Record the unchanged host-profile SHA256 with both results. Candidate artifacts have their own recorded hashes; never replace the Base profile's neutral artifact hashes with candidate hashes. Build the candidate separately and verify its source and embedded BPF path before execution. The frozen A/B/C/D runner intentionally accepts only neutral Base, so do not bypass its identity guard for policy runs.

Compare each candidate directly with neutral Base under identical conditions. For a load hypothesis, compare Base and policy under the same documented load, CPU placement and load parameters; do not compare an unloaded Base with a loaded candidate. Preserve the Base repetition, warm-up, workload, metric and statistical conventions when applicable, and state any experimental protocol difference in advance.

Detect topology once at experiment startup with `bench/detect_host_topology.sh`. Keep all detected core classes visible. Do not rediscover topology in hot scheduler callbacks. Keep bounded load sampling outside callbacks. Phase policies consume the existing compact phase state; do not add phase histories or per-token timing hooks. Check readiness and machine state outside timed requests.

Store each comparison under ignored `benchmark-results/season2/<hypothesis>/<UTC-run-id>/`, with `base/` and `candidate/` raw directories, the exact `host-profile.json`, manifest, hypothesis, source/artifact hashes, commands, workload, load parameters, raw responses, readiness/cleanup evidence, summary and `report.md`. Record the pairing/order and analysis seed. The report states whether thermal validation was available. Retain failed/incomplete runs and every issued request; no replacement samples or outlier removal. Explain failures without hiding their evidence.

Share the entire result directory, including both raw sides and all identity records, so a teammate can inspect the comparison without manually supplied host values. Review the hypothesis, narrow source diff, validity, spread and paired results before adopting a policy. Keep policy conclusions separate from portable Base correctness.
